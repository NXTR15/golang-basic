## 2. Module, package, dan layout

| Istilah | Arti | Padanan Java |
|---|---|---|
| **Module** | unit versi & dependency, satu `go.mod` di root repo | `pom.xml` / project Maven |
| **Package** | satu folder berisi file `.go` dengan deklarasi `package` sama | Java package (tapi dipetakan ke folder, bukan nama bertitik) |

Satu module berisi banyak package.

```
module github.com/NXTR15/golang-basic
```

Module path = **URL repo tanpa `https://` dan tanpa `.git`**. Ini bukan formalitas: Go tidak punya
Maven Central, `go get` mengambil kode langsung dari URL module. Kalau module path tidak sama dengan
lokasi repo sesungguhnya, package tidak bisa diimport orang lain — dan import antar package di dalam
proyek sendiri juga memakai prefix ini.

Konvensi folder yang dipakai proyek ini:

```
golang-basic/
├── go.mod
├── cmd/shortener/main.go   ← entrypoint; satu folder per binary
├── internal/               ← kode yang HANYA bisa diimport module ini (mulai S2)
└── docs/                   ← catatan belajar
```

`internal/` bukan konvensi sosial — compiler Go **menolak** import dari luar module.
Pengganti `private` pada level package.

## 3. Visibility: huruf besar/kecil, bukan keyword

Tidak ada `public` / `private` / `protected` di Go.

```go
func NewLink()  // diekspor (exported)   — bisa dipakai package lain   ≈ public
func newLink()  // tidak diekspor        — hanya di dalam package-nya  ≈ package-private
```

Berlaku untuk **semua** identifier: fungsi, tipe, variabel, konstanta, bahkan field struct.
Tidak ada padanan `protected` karena tidak ada inheritance.

Istilah yang benar adalah **exported / unexported**, bukan public/private.

## 4. `var` vs `:=` dan zero value

```go
var count int        // deklarasi; zero value 0 (BUKAN null)
var name = "nex"     // deklarasi + tipe disimpulkan compiler
name := "nex"        // bentuk pendek — HANYA valid di dalam fungsi
```

Dua aturan yang menyandung pemula:

1. `:=` **mendeklarasikan variabel baru** sekaligus mengisi. `=` hanya mengisi yang sudah ada.
2. Variabel lokal yang dideklarasikan tapi tidak dipakai = **compile error**, bukan warning.

**Tidak ada `null` untuk tipe dasar.** Setiap tipe punya zero value:

| Tipe | Zero value |
|---|---|
| `int`, `float64` | `0` |
| `string` | `""` |
| `bool` | `false` |
| pointer, slice, map, interface, channel, func | `nil` |

Ini menghapus satu kelas bug yang di Java dilawan dengan `Optional`.

### Kenapa "declared and not used" itu error

```
cmd\shortener\main.go:16:2: declared and not used: unused
```

Tiga alasan praktis:

1. **Variabel tak terpakai hampir selalu bug.** Pola paling umum: menghitung sesuatu, salah ketik
   nama, lalu memakai variabel lain. Compiler menangkapnya sebelum runtime.
2. **Warning yang bisa diabaikan = warning yang diabaikan.** Go sengaja tidak punya level tengah.
   Kode yang compile adalah kode yang bersih; tidak ada debat gaya di PR.
3. **Compile cepat.** Aturan sederhana dan keras lebih murah daripada static analyzer pintar.

**Batas aturannya** (sering ditanya di interview):
- Hanya berlaku untuk **variabel lokal**.
- Package-level `var` dan `const` tak terpakai → boleh.
- **Import** tak terpakai → error, sama kerasnya.

Blank identifier `_` untuk membuang nilai secara sengaja:

```go
_ = hitungSesuatu()        // nilai sengaja dibuang
val, _ := strconv.Atoi(s)  // error sengaja diabaikan (berbahaya — lihat S3)
```

`_` bukan variabel: tidak bisa dibaca, tidak memakan memori. Cara bilang ke compiler
"aku sadar, ini memang kubuang".

## 5. Urutan startup program Go ← titik lemah, ulangi

Urutan yang **benar**:

1. Semua package yang diimport diinisialisasi dulu (rekursif, dari paling dalam).
2. Dalam satu package: semua **package-level `var`** diinisialisasi — termasuk yang nilainya
   datang dari pemanggilan fungsi.
3. Fungsi `init()` dijalankan (boleh lebih dari satu, bahkan di file berbeda).
4. **Baru** `main()` dipanggil.

```go
var total = hitung()        // jalan DULU

func hitung() int {
	fmt.Println("hitung dipanggil")
	return 10
}

func main() {
	fmt.Println("main mulai")   // jalan KEDUA
}
```

Output: `hitung dipanggil` → `main mulai`.

### Urutan penulisan di file TIDAK menentukan apa pun

Go menganalisis **dependency** antar deklarasi, lalu menginisialisasi sesuai kebutuhan:

```go
var a = b + 1   // a butuh b
var b = 2       // ditulis setelah a, tapi diinisialisasi lebih dulu
// hasil: a == 3
```

Ini sah di Go. Java menolaknya (*illegal forward reference*; static initializer berjalan
top-to-bottom tekstual). Yang Go tolak hanya **siklus**:
`var a = b; var b = a` → `initialization cycle`.

### Implikasi praktis

- Kalau fungsi di package-level `var` membaca env var, buka file, atau connect DB, itu jalan
  **sebelum** `main()` bisa memasang logger atau membaca flag. Error di situ tidak bisa ditangani
  rapi — tidak ada tempat mengembalikan `error`, langsung panic.
  **Konvensi Go: package-level `var` hanya untuk nilai murni; semua yang bisa gagal diletakkan
  di `main()`.** Inilah salah satu alasan Go tidak butuh DI container — wiring eksplisit di
  `main()` (dipraktikkan di P2.S8).
- `init()` dengan side effect adalah magnet bug. Pola `import _ "github.com/lib/pq"` (underscore)
  adalah import semata-mata agar `init()`-nya jalan dan mendaftarkan driver DB — dipakai di P2.S7.

## 6. Verb format `fmt`

| Verb | Untuk |
|---|---|
| `%d` | integer desimal |
| `%s` | string |
| `%q` | string dengan kutip ganda, **atau rune** kalau argumennya integer |
| `%t` | bool |
| `%v` | apa saja, format default |
| `%+v` | struct lengkap dengan nama field — paling berguna saat debug |
| `%T` | **tipe** dari nilainya |

### Bug yang dialami: `%q` pada integer

```go
fmt.Printf("len%q\n", len(args))   // mencetak: len'\x01'
```

`%q` pada `int` menafsirkannya sebagai **rune/code point**, bukan angka. Code point 1 adalah
karakter kontrol tak tercetak, jadi muncul sebagai escape `'\x01'`. Verb yang benar: `%d`.

**`%T` adalah alat diagnosis terbaik di bulan pertama.** Setiap kali output aneh, cetak `%T` dulu.

### `go vet` menangkap kelas bug ini

Format string hanyalah string biasa bagi compiler, jadi ketidakcocokan verb tidak terdeteksi
saat compile. Yang menangkapnya:

```bash
go vet ./...
```

Sudah terpasang bersama toolchain, tanpa install apa pun. **Biasakan `go vet` sebelum commit.**

### Dua jenis string literal

```go
"butuh 1 argumen\n"   // interpreted — \n jadi newline, \t \" berlaku
`butuh 1 argumen\n`   // raw (backtick) — escape TIDAK diproses, tercetak literal \n
```

Backtick: apa yang ditulis itu yang tersimpan, boleh multi-baris, tidak ada escape.
Dipakai sehari-hari untuk **query SQL multi-baris** (P2.S7) dan **regex** (`\d` tidak perlu `\\d`).

## 7. `os.Args` — argumen command line

Bertipe `[]string` (slice of string), **bukan** `String[] args` seperti Java.

**`os.Args[0]` adalah path program itu sendiri**, bukan argumen pertama pengguna.
Java `main(String[] args)` tidak menyertakannya; Go menyertakan.

```
shortener.exe https://go.dev
└─ os.Args[0] = path ke shortener.exe
   os.Args[1] = "https://go.dev"
```

| Tanpa argumen | `len(os.Args)` = 1 |
| Satu URL | `len(os.Args)` = 2 |

### Slicing vs indexing — beda satu karakter `:`

```go
os.Args        // []string  — seluruh argumen
os.Args[1:]    // []string  — SLICING, dipotong dari indeks 1 → tetap slice
os.Args[1]     // string    — INDEXING, mengambil satu elemen → nilai tunggal
```

Kurung siku **dengan** titik dua = slicing, hasilnya slice.
Kurung siku **tanpa** titik dua = indexing, hasilnya elemen.
(Padanan kasar `substring` vs `charAt` di Java.)

Bug yang dialami: `fmt.Printf("url=%v", os.Args[1:])` mencetak `url=[https://go.dev]` —
kurung siku muncul karena nilainya masih **slice**, bukan string.

### `len()` menghitung ELEMEN, bukan "kalimat"

| Ekspresi | Elemennya apa | Hasil |
|---|---|---|
| `len([]string{"https://go.dev"})` | string | `1` |
| `len("https://go.dev")` | **byte** | `14` |
| `len("héllo")` | byte | `6` (bukan 5 — `é` = 2 byte UTF-8) |

`len` pada string = **jumlah byte**, bukan karakter. Untuk ASCII keduanya sama. Rune dibahas di S4.

### Panic, bukan NullPointerException

Mengakses `os.Args[1]` saat argumen kosong → **panic** `index out of range`.
**Pemeriksaan panjang harus mendahului pengaksesan. Urutannya tidak boleh dibalik.**

## 8. `Print` vs `Fprint` vs `Sprint`

Satu aturan, tiga keluarga — perhatikan awalan namanya:

| Nama | Tujuan tulisan | Padanan Java |
|---|---|---|
| `Print`, `Printf`, `Println` | **selalu** stdout | `System.out.print...` |
| `Fprint`, `Fprintf`, `Fprintln` | **writer yang ditentukan** di argumen pertama | `writer.write(...)` |
| `Sprint`, `Sprintf`, `Sprintln` | tidak menulis ke mana pun — **mengembalikan `string`** | `String.format(...)` |

**`F` = file/writer. `S` = string. Tanpa awalan = stdout.**

Ketiga baris ini hasilnya identik:

```go
fmt.Println("halo")
fmt.Fprintln(os.Stdout, "halo")   // Println hanyalah ini dengan os.Stdout dipatok
s := fmt.Sprintln("halo"); os.Stdout.WriteString(s)
```

### Kenapa `Fprint` penting: `io.Writer`

Argumen pertamanya bertipe `io.Writer` — sebuah **interface dengan satu method**
(`Write([]byte) (int, error)`). Apa pun yang punya method itu bisa masuk:

```go
fmt.Fprintf(os.Stderr, ...)     // stream error di terminal
fmt.Fprintf(file, ...)          // file di disk
fmt.Fprintf(w, ...)             // http.ResponseWriter → cara menulis HTTP response (P2.S5)
fmt.Fprintf(&buf, ...)          // bytes.Buffer di memori → cara menangkap output dalam test
fmt.Fprintf(gzipWriter, ...)    // terkompresi on the fly
```

Fungsi yang sama, tujuan berbeda, tanpa satu pun `if`.
**Interface kecil adalah unit komposisi utama di Go.** Spring mencapai fleksibilitas setara lewat
annotation dan proxy; Go mencapainya lewat interface satu-method yang dilewatkan sebagai nilai
biasa. Dibahas tuntas di S2.

### Kebiasaan yang harus dibentuk sekarang

**Data ke stdout, diagnosis ke stderr.**

`docker logs` dan hampir semua log collector memisahkan dua stream itu. Output data yang tercampur
pesan error merusak pipeline (`cmd > hasil.txt`).

## 9. Exit code

Kontrak dengan dunia luar: shell, CI, Docker, Kubernetes.

| Code | Arti |
|---|---|
| `0` | sukses |
| `1` | error umum ← **default yang benar** |
| lain | hanya jika program sengaja mendefinisikan arti per angka **dan mendokumentasikannya** |

Setelah stderr + exit code dipakai, kata `error:` di dalam pesan jadi mubazir —
`curl` dan `git` cukup menulis pesannya saja.

### Menguji exit code dengan benar

`go run` **menelan** exit code program dan melaporkannya sebagai `exit status N` miliknya sendiri.
Uji pada binary hasil build:

```powershell
go build -o bin\shortener.exe ./cmd/shortener
.\bin\shortener.exe
echo $LASTEXITCODE
```

## 10. `go run` vs `go build`

| Perintah | Perilaku |
|---|---|
| `go run ./cmd/shortener` | compile ke direktori temporer, jalankan, buang |
| `go build -o bin\shortener.exe ./cmd/shortener` | hasilkan **satu file berisi seluruh runtime Go** |

Binary hasil `go build` tidak butuh Go terinstall di mesin tujuan, tidak butuh JVM, start dalam
milidetik. Itulah file yang nanti dimasukkan ke image Docker di Bagian terakhir.

**Catatan gaya:** `gofmt` memakai **tab**, bukan spasi, dan itu tidak bisa dinegosiasi.
Jangan atur editor pakai spasi untuk Go.
